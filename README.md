# Zabbix-шаблон: ТС ПИоТ (ЕСМ) + ЛМ ЧЗ

Шаблон мониторинга кассовых узлов с локальным модулем «Честного Знака» (ЛМ ЧЗ) и транспортным модулем ЕСМ/ТС ПИоТ для **Zabbix 8.0**.

## Что мониторит

**Службы (service.info, state):**
- ЕСМ: `esm-orchestrator`, `epc-bridge`, `esm-lm-controller`, кассовый модуль `esm-cm-<серийник>` (имя — макросом `{$TPIOT.SVC.CM}` на хосте);
- ЛМ ЧЗ: `regime` (основная служба, nssm), `yenisei` (синхронизация локальной БД, лимит устаревания 72 ч).

**Порты:** 51401 (API ЕСМ), 50063 (контроллер ЛМ ЧЗ, фиксированный — при закрытии касса получает ошибку 514), 5995 (API ЛМ ЧЗ).

**Статус модуля (главная фича):** HTTP-агент айтем `lm.status` опрашивает
`GET http://{HOST.IP}:5995/api/v2/status` (без авторизации) и извлекает `$.status`:

- триггер **HIGH** — `not_configured`: модуль работает, порты слушаются, но локальная БД справочников не загружена (dbState пустой). Это состояние **невидимо** для триггеров на службы и порты — узел выглядит «зелёным», а проверка кодов маркировки не работает. Устраняется локальной инициализацией на узле;
- триггер **WARNING** — `nodata(15m)`: API статуса не отвечает (порт закрыт, модуль не установлен — слепая зона `service.info=255`, ответ не-200). С ручным закрытием (manual close).

## Импорт

UI: Data collection → Templates → Import → выбрать YAML. Галочки «Delete missing» не включать, если не хотите удалять существующие элементы шаблона.

API (Zabbix 8.0): скрипт `import_template.mjs`:

```bash
ZABBIX_API=http://zabbix/api_jsonrpc.php ZABBIX_TOKEN=<токен> node import_template.mjs template_ts_piot_ecm_lm_cz_8.0.yaml
```

## Макросы

| Макрос | По умолчанию | Описание |
|---|---|---|
| `{$TPIOT.SVC.CM}` | `esm-cm-0000000000000` | Имя службы кассового модуля ЕСМ (`esm-cm-<серийник>`). **Переопределить на каждом хосте!** |
| `{$TPIOT.CHECK.CM}` | `0` | `1` = следить за кассовым модулем ЕСМ (включать после задания имени службы) |
| `{$TPIOT.CHECK.PORTS}` | `1` | `1` = проверять порты 51401/50063/5995 |

## Нюансы формата экспорта (6.x–8.0)

- триггеры в YAML-экспорте вкладываются внутрь айтемов (`items[].triggers`); секции `triggers` на уровне шаблона не существует — валидные места: внутри айтема или `zabbix_export.triggers` на верхнем уровне (для триггеров по нескольким айтемам);
- `uuid` обязателен для всех сущностей;
- значения полей с `:` внутри (например, `Имя: пояснение`) нужно брать в кавычки, иначе импортёр падает по YAML-парсингу.

## Совместимость

Проверен на Zabbix 8.0.0 (реальный импорт), ЛМ ЧЗ 2.6.1-7 / 2.6.3-4 (служба `regime`, стек Cowboy/Erlang).

| Версия Zabbix | Файл |
|---|---|
| 8.0 | `template_ts_piot_ecm_lm_cz_8.0.yaml` |
| 7.4 | `template_ts_piot_ecm_lm_cz_7.4.yaml` |
| 7.0 | тот же `_7.4.yaml`, смените `version: '7.4'` на `'7.0'` |
| 6.4 | `template_ts_piot_ecm_lm_cz_6.4.yaml` |
| 6.0–6.2 | тот же `_6.4.yaml`, смените `version: '6.4'` на свою |
| ≤5.4 | не поддерживается: другой синтаксис триггеров и структура экспорта |

Все три YAML отличаются только строкой `version` — структура одинакова: триггеры вложены внутрь айтемов, как в официальных шаблонах Zabbix. Структура сверена с официальными экспортами веток release/6.0, release/7.0, release/7.4, release/8.0 репозитория zabbix/zabbix; на живом сервере проверен только 8.0 (реальный импорт).
